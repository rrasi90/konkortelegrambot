# راهنمای کوتاه Open Design برای AEL

## چه چیزی نصب شد

نسخهٔ دسکتاپ <bdi>Open Design</bdi> نسخهٔ ۰٫۲۷٫۱ با <bdi>winget</bdi> نصب شد. لاگ نصب پایان موفق را نشان می‌دهد و فایل اجرایی در این مسیر است:

`C:\Users\rrasi_oorj8fq\AppData\Local\Programs\Open Design\Open Design.exe`

این ابزار یک وابستگی اجرایی پروژه نیست. در `package.json` چیزی اضافه نشد و سورس AEL به آن وابسته نیست.

## این ابزار چه می‌کند

فضای طراحی <bdi>Open Design</bdi> محلی و متن‌باز است و یک عامل کدنویسی نصب‌شده روی سیستم را به موتور طراحی تبدیل می‌کند. خروجی آن فایل‌های واقعی <bdi>HTML</bdi> است، نه تصویر صرف. ایده‌ها، سیستم طراحی، پیش‌نمایش و بازخورد در یک پروژه کنار هم قرار می‌گیرند.

قابلیت‌های مهم برای این پروژه:

- سیستم‌های طراحی آماده با رنگ، تایپوگرافی، فاصله و مؤلفه‌ها.
- ساخت پیش‌نمایش زندهٔ وب، اپ، داشبورد و اسلاید.
- اتصال به عامل‌های کدنویسی محلی از راه <bdi>MCP</bdi> یا حالت اجرای محلی.
- ذخیرهٔ فایل‌ها روی همین دستگاه و امکان بازبینی آن‌ها پیش از ورود به پروژه.
- مجوز <bdi>Apache 2.0</bdi> و امکان بازبینی و تغییر مهارت‌ها و سیستم‌های طراحی.

## بهترین نوع استفاده در AEL

### ۱. استفادهٔ اصلی: کارگاه طراحی مستقل

برای هر تغییر ظاهری، یک پروژهٔ جدا در <bdi>Open Design</bdi> بساز و فقط همان صفحه یا مؤلفه را در آن آزمایش کن. سپس تصمیم‌های بصری را به‌صورت دستی به `src/` منتقل کن. این روش با قاعدهٔ فعلی پروژه هم‌خوان است: تغییر ظاهری نباید موتور، داده، احراز هویت یا ذخیره‌سازی را عوض کند.

### ۲. ورودی‌هایی که باید به ابزار بدهی

- محدودیت‌ها و نقشهٔ بازطراحی در فایل `docs/design/MINIAPP_REDESIGN_PLAN_FA.md` آمده است.
- مرجع بصری فعلی فایل `docs/design/prototypes/ael-today-v2.html` است.
- مهارت `.agents/skills/elite-frontend-ux/SKILL.md` نسبت رنگ ۶۰-۳۰-۱۰، حداقل اندازهٔ متن و هدف لمسی را تعیین می‌کند.
- فایل‌های فارسی موجود برای حفظ نیم‌فاصله، گیومه و ارقام فارسی.

### ۳. خروجی درست از ابزار

خروجی را به‌صورت یک صفحهٔ مستقل <bdi>HTML</bdi> بگیر، نه یک بازنویسی کامل اپ. بعد این موارد را جدا کن:

- توکن‌های رنگ، فاصله و گردی گوشه.
- ساختار سلسله‌مراتب صفحه.
- حالت‌های خالی، بارگذاری و خطا.
- رفتار موبایل و دسکتاپ.

سپس فقط همین تصمیم‌ها را در کامپوننت‌های React پروژه پیاده کن. فایل‌های تولیدشدهٔ ابزار را مستقیم داخل `src/` نگذار.

### ۴. استفاده از <bdi>MCP</bdi> فقط در صورت نیاز

دستور نصب <bdi>MCP</bdi> برای چند عامل شناخته‌شده در <bdi>Open Design</bdi> وجود دارد، مثلاً:

```bash
od mcp install claude
od mcp install codex
od mcp install cursor
```

اتصال <bdi>Freebuff</bdi> در فهرست رسمی این نسخه نیست. بنابراین بهترین مسیر فعلی، استفادهٔ مستقیم از اپ دسکتاپ و انتقال دستی نتیجه است. اتصال <bdi>MCP</bdi> فقط وقتی معنا دارد که یک عامل پشتیبانی‌شده بخواهد مهارت‌های طراحی را از داخل جریان کاری خود صدا بزند.

### ۵. آنچه نباید انجام شود

- افزودن <bdi>Open Design</bdi> به وابستگی‌های زمان اجرا یا باندل مینی‌اپ.
- دادن کلیدهای سرور یا اطلاعات کاربران به پروژهٔ طراحی.
- جایگزینی مستقیم فایل‌های تولیدی ابزار با کد اپ بدون بازبینی.
- ساخت صفحهٔ تزئینی و شلوغ که با قاعدهٔ «یک اقدام اصلی در هر صفحه» و رنگ محدود پروژه تضاد داشته باشد.

## جمع‌بندی

برای AEL، <bdi>Open Design</bdi> یک ابزار پژوهش و نمونه‌سازی بصری است، نه بخشی از معماری محصول. بهترین استفاده این است: طراحی مستقل و محلی، گرفتن خروجی <bdi>HTML</bdi>، استخراج توکن‌ها و الگوها، و پیاده‌سازی کنترل‌شده در React. اتصال <bdi>MCP</bdi> یک گزینهٔ بعدی است، نه پیش‌نیاز.
