# سناریوهای پذیرش موتور

این سناریوها الزامات آزمون‌اند؛ تکمیل سند به‌تنهایی به معنی سبز بودن آزمون نیست.

| شناسه | سناریو | رفتار قابل قبول |
|---|---|---|
| A-01 | پاسخ غلط با اطمینان بالا | اولویت بررسی بیشتر؛ بدون اعلام قطعی ضعف کل فصل |
| A-02 | پاسخ غلط با خوداظهاری بی‌دقتی | شواهد تکمیلی روی همان مهارت؛ روابط دوردست فعال نشوند |
| A-03 | پیش‌نیاز تأییدشده | فقط یک probe برای پیش‌نیاز مستقیم انتخاب شود |
| A-04 | یال پیشنهادی AI | در برنامهٔ اجباری اثری نداشته باشد |
| A-05 | پاسخ درست حدسی | شواهد ضعیف بماند و در آینده با سؤال تازه بررسی شود |
| A-06 | سؤال معیوب/کلید مشکوک | از به‌روزرسانی دانش کاربر جلوگیری و آیتم قرنطینه شود |
| A-07 | بودجهٔ روزانه کم | دقیقهٔ برنامه‌ریزی‌شده از سقف بیشتر نشود و اولویت‌ها ثبت شوند |
| A-08 | حالت در مسیر | سؤال نیازمند کاغذ و قلم انتخاب نشود |
| A-09 | ارزیابی مستقل | آیتم holdout در تمرین عادی قابل مشاهده یا انتخاب نباشد |
| A-10 | درخواست تکراری | همان idempotency key دوباره اثر یادگیری/ترمیم ایجاد نکند |
| A-11 | نزدیک‌شدن آزمون | فوریت و پوشش‌نشدگی بر اولویت اثر بگذارد؛ عدم امکان پوشش شفاف اعلام شود |
| A-12 | محتوای تأییدنشده | کاربر نهایی آن را نبیند |
| A-13 | بازگشت پس از چند روز غیبت | برنامه از سقف روزانه بیشتر نشود؛ عقب‌افتادگی بازتنظیم و شفاف اعلام شود |
| A-14 | قطع اینترنت وسط جلسه | پاسخ‌ها در صف محلی بمانند و بعداً با idempotency ارسال شوند؛ جلسه قابل ادامه باشد |
| A-15 | گزارش اشکال سؤال توسط کاربر | آیتم موقتاً از انتخاب خارج و برای بازبینی ثبت شود؛ به کاربر بازخورد داده شود |
| A-16 | بودجه کمتر از کوچک‌ترین فعالیت | فعالیت کوتاه جایگزین یا پیام شفاف؛ برنامهٔ خالی بی‌صدا نباشد |
| A-17 | رکورد فعالیت نامعتبر (NaN، منفی) | فقط همان رکورد رد و ثبت شود؛ کل برنامه شکست نخورد |
| A-18 | تمام‌شدن سؤال دیده‌نشده برای یک مهارت | وضعیت «اثبات ناممکن» شفاف باشد؛ verified_by_unseen اعلام نشود |
| A-19 | تمرین آزاد موضوعی | شواهد با برچسب حالت آزاد ثبت شود و برنامه‌ریز را بی‌دلیل خراب نکند |
| A-20 | درخواست‌های پی‌درپی برای جمع‌آوری سؤال‌ها | محدودیت نرخ و سقف روزانه؛ رفتار مشکوک ثبت شود |
| A-21 | هفتهٔ آخر قبل از آزمون | سهم یادگیری جدید با فاصله تا آزمون تنظیم شود و مرور/شبیه‌ساز اولویت یابد |
| A-22 | متن مخلوط فارسی-انگلیسی و ارقام فارسی | نمایش RTL درست؛ جست‌وجو و حذف تکرار با نرمال‌سازی (ی/ک و ارقام) |
| A-23 | کاربر فعالیت را رد می‌کند (این را بلدم / بعداً) | به‌عنوان رویداد ثبت شود، بدون جریمهٔ خودکار مهارت؛ در برنامهٔ بعد اثر شفاف داشته باشد |

معیارهای CI برای نسخهٔ پایه: typecheck، آزمون موتور و build هر دو برنامه. آزمون‌های پایگاه داده، RLS، Telegram initData، browser E2E و device E2E پیش از اتصال واقعی هنوز باید اضافه و اجرا شوند.

سناریوهای A-13 تا A-23 از مرور کاربرمحور (walkthrough) به‌دست آمده‌اند و هنوز هیچ‌کدام پیاده‌سازی یا اجرا نشده‌اند.
