# سناریوهای پذیرش موتور

این سناریوها الزامات آزمون‌اند؛ تکمیل سند به‌تنهایی به معنی سبز بودن آزمون نیست.

| شناسه | سناریو | رفتار قابل قبول |
|---|---|---|
| A-01 | پاسخ غلط با اطمینان بالا | اولویت بررسی بیشتر؛ بدون اعلام قطعی ضعف کل فصل |
| A-02 | پاسخ غلط با خوداظهاری بی‌دقتی | شواهد تکمیلی روی همان مهارت؛ روابط دوردست فعال نشوند |
| A-03 | پیش‌نیاز تأییدشده | فقط یک probe برای پیش‌نیاز مستقیم انتخاب شود |
| A-04 | یال پیشنهادی AI | در برنامهٔ اجباری اثری نداشته باشد |
| A-05 | پاسخ درست حدسی | شواهد ضعیف بماند و در آینده با سؤال تازه بررسی شود |
| A-06 | سؤال معیوب/کلید مشکوک | از به‌روزرسانی دانش کاربر جلوگیری و آیتم قرنطینه شود |
| A-07 | بودجهٔ روزانه کم | دقیقهٔ برنامه‌ریزی‌شده از سقف بیشتر نشود و اولویت‌ها ثبت شوند |
| A-08 | حالت در مسیر | سؤال نیازمند کاغذ و قلم انتخاب نشود |
| A-09 | ارزیابی مستقل | آیتم holdout در تمرین عادی قابل مشاهده یا انتخاب نباشد |
| A-10 | درخواست تکراری | همان idempotency key دوباره اثر یادگیری/ترمیم ایجاد نکند |
| A-11 | نزدیک‌شدن آزمون | فوریت و پوشش‌نشدگی بر اولویت اثر بگذارد؛ عدم امکان پوشش شفاف اعلام شود |
| A-12 | محتوای تأییدنشده | کاربر نهایی آن را نبیند |

معیارهای CI برای نسخهٔ پایه: typecheck، آزمون موتور و build هر دو برنامه. آزمون‌های پایگاه داده، RLS، Telegram initData، browser E2E و device E2E پیش از اتصال واقعی هنوز باید اضافه و اجرا شوند.
