# قرارداد محتوا و راهنمای افزودن درس برای ایجنت

## نقشهٔ فایل‌ها

- `content/learning-courses/financial-management.json` نمونهٔ کامل درس با منبع، پیش‌نیاز، مثال و سؤال تألیفی است.
- `apps/worker/src/learning-catalog.ts` فهرست مشترک Worker و فایل آفلاین است.
- `packages/learning-engine/src/formative-quiz.ts` قرارداد TypeScript و قواعد انتخاب و تصحیح سؤال است.
- `apps/worker/src/learning-paths.ts` احراز مالکیت جلسه، نسخه و محدودیت زمانی را مدیریت می‌کند.
- `apps/miniapp/learning.js` نمایش مشترک مینی‌اپ و فایل آفلاین است.
- `tools/offline/adapter.ts` اجرای محلی را به همان موتور وصل می‌کند.
- `scripts/build-question-index.mjs` فهرست شناسنامه‌ای دو بانک ردیابی‌شده را از دادهٔ پروژه و نگاشت‌های `content/knowledge/syllabus-nodes.json` تولید می‌کند. خروجی `content/learning-evidence/question-index.json` فقط فراداده است و سؤال، کلید و متن ارجاع آزاد را شامل نمی‌شود. نام درس و فصل نگاشت موجود است و بررسی نشده است.

## قرارداد حداقلی

| سطح | فیلدهای لازم | قاعده |
|---|---|---|
| بسته | `schemaVersion`، `id`، `version`، `title`، `status`، `description`، `scopeNote`، `sources`، `topics`، `questions` | نام فایل برابر `id.json` و `status=authored_pilot` |
| منبع | شناسه، عنوان، URL امن، بخش یا فصل، نوع و تاریخ بررسی | هر شناسه سراسری یکتا و ارجاع دقیق باشد |
| مبحث | شناسه، عنوان، هدف، دقیقه، پیش‌نیازها، مفاهیم، فرمول، مثال، دام و منابع | مبحث پیش‌نیاز زودتر در آرایه می‌آید. ترتیب وابستگی دور ندارد. |
| سؤال | شناسه، شناسه مبحث، دشواری، صورت، چهار گزینه، اندیس صحیح، توضیح، چهار دلیل، منابع، منشأ، حقوق و بازبینی | اندیس صفرمبنا. سؤال تألیفی و وضعیت بازبینی صریح باشد. |
| سؤال تشریحی | فیلدهای مشترک، `kind=essay`، پاسخ نمونه در `explanation`، آرایهٔ `rubric` و `readingBlock` | `choices` و `optionReasons` خالی‌اند و `answerIndex=-1` نشان‌دهندهٔ نبود گزینهٔ صحیح است. قبل از ثبت پاسخ، پاسخ نمونه و معیارها به کلاینت آنلاین ارسال نمی‌شوند. |
| گروه نسخه‌های هم‌ارز | فیلد اختیاری `variantGroup` روی سؤال | فقط پس از بررسی کارشناسی، شناسهٔ یکسان به نسخه‌هایی داده شود که نباید هم‌زمان در یک آزمون بیایند؛ مقدار با حروف کوچک انگلیسی، رقم، نقطه، خط تیره یا زیرخط. حذف فیلد یعنی هر سؤال مستقل است. |
| شواهد تاریخی | مقطع، سال، کد، شماره، شناسهٔ سؤال و وضعیت ردیابی | در بستهٔ تألیفی وارد نشود. مسیر جدا در سند ۰۶ دارد. |

## دستورالعمل افزودن درس

1. **واحد کار را تعریف کن.** مشخص کن کاربر بعد از درس چه مسئله‌ای را می‌تواند حل کند. پنج تا هشت مبحث کوچک برای نخستین بسته کافی است.
2. **منابع را بررسی کن.** صفحه یا فصل معتبر را ثبت کن. مثال و متن تازه بنویس. سؤال رسمی با حقوق نامعلوم را وارد تمرین عمومی نکن.
3. **از نمونه کپی کن.** فایل JSON تازه با شناسهٔ پایدار بساز. برای نمونه شناسهٔ `operations-research` و مبحث `or.linear-model`. برای هر مبحث حداقل یک تمرین معتبر، ترجیحاً سه تمرین با دشواری پایه و کاربردی بده.
4. **جواب را دوباره حل کن.** مقدار درست، واحد، گردکردن، نشانه‌ها و امکان وجود دو گزینهٔ درست را جدا بررسی کن. علت هر گزینه به همان گزینه مربوط باشد. `pending_sme` را فقط پس از بازبینی متخصص به `reviewed` تغییر بده.
5. **یک بار ثبت کن.** فایل را در `learning-catalog.ts` وارد کن و به آرایهٔ `learningCourses` اضافه کن. برای نمایش درس تازه، UI و endpoint جدید لازم نیست.
6. **اعتبارسنجی و بازتولید کن.** فرمان‌های زیر را اجرا کن. برای تغییر محتوای سؤال موجود، نسخهٔ بسته را بالا ببر تا جلسهٔ ذخیره‌شده با پاسخ تازه مخلوط نشود.

```sh
npm run validate:learning
npm test
npm run build:offline
npm run audit:miniapp
```

پس از تغییر بانک‌های ردیابی‌شده یا سرفصل‌ها، `node scripts/build-question-index.mjs` را اجرا کن. اعتبارسنجی سازگاری فهرست نیز بخشی از `npm run validate:learning` است. منشأ و کلید رکوردها باید مستقل از شناسهٔ گره بررسی شود.

7. **در مرورگر بررسی کن.** HTML را مستقیم باز کن و آزمون دستی سند ۰۸ را اجرا کن. مسیر آنلاین را با `npm run dev:miniapp` آزمایش کن.
8. **تغییرات را گزارش کن.** نام درس، تعداد موضوع و سؤال، منشأ، موارد باز و شناسهٔ تست‌های نمونه را یادداشت کن.

## حداقل قواعد تغییر

شناسهٔ مبحث و سؤال را برای رکورد معتبر بازاستفاده نکن. اصلاح متن یا گزینه همراه با افزایش نسخه ثبت شود. تغییر مفهومی سؤال به شناسهٔ جدید نیاز دارد. فایل HTML تولیدشده است. محتوای آن را دستی ویرایش نکن. این قرارداد برای تمرین تألیفی است. واردکردن سؤال رسمی به جریان اصلی به حقوق، شمارهٔ دقیق، کلید معتبر، نسخه و پذیرش دادهٔ جداگانه نیاز دارد.

نمونهٔ سؤال تشریحی در `content/learning-courses/statistics-foundations.json` با شناسهٔ `stat.center.essay01` قرار دارد. یک پاسخ نوشته‌شده تا تصحیح انسانی در وضعیت `pending` می‌ماند. خودارزیابی کاربر به‌صورت جداگانه ذخیره می‌شود و نمرهٔ رسمی یا شاهد تسلط نیست. متن پاسخ، حداکثر ۵۰۰۰ نویسه است. در نسخهٔ آفلاین پاسخ نمونه داخل فایل محلی وجود دارد.


## افزودهٔ لایه اول — Taxonomy، گراف معنایی و اتصال سرفصل

مرجع مشترک این ساختارها:
- قراردادها: `packages/contracts/src/academic-foundation.ts`
- داده پایه و crosswalk: `content/knowledge/academic-foundation.v1.json`
- شرح تصمیم‌ها و شکاف‌های موجود: `docs/architecture/LAYER_1_ACADEMIC_FOUNDATION_FA.md`
- گزارش موجودی و موارد حل‌نشده: `docs/audit/LAYER_1_CURRENT_STATE_AND_GAPS_FA.md`

### قواعد اجباری هنگام افزودن یا اصلاح درس

1. برای رشته، گرایش، CourseDefinition و SyllabusNode، رجیستری آموزشی را گسترش بده؛ فایل موازی برای همان مفهوم نساز.
2. کد مجموعه آزمون، کد ترکیب، کد دفترچه، studyTrack و examLevel را جدا نگه دار.
3. ضریب رسمی، scope ضریب و learningPriorityWeight سه داده مستقل‌اند. اگر ضریب رسمی معلوم نیست null ثبت کن.
4. Tag را با Skill یکی نکن. Skill باید تعریف عملیاتی و شاهد سنجش داشته باشد؛ Tag برای جست‌وجو و طبقه‌بندی است.
5. رابطه prerequisite را در گراف پیش‌نیاز موجود نگه دار. برای related_to، confusable_with، contrasts_with و روابط معنایی از KnowledgeRelation استفاده کن.
6. هیچ parent، Skill، Tag، Outcome یا relation را صرفاً برای پرشدن نمودار حدس نزن. شناسهٔ نامعلوم در وضعیت needs_mapping یا needs_review باقی بماند.
7. هر سؤال جدید باید تا حد امکان primaryNodeId و primarySkillId روشن داشته باشد؛ secondaryها فقط با دلیل وارد شوند.
8. هر Topic درسنامه باید به یک syllabusNodeId متصل شود، اگر معادل دقیق آن وجود دارد. اگر وجود ندارد، null و status=needs_mapping بماند.
9. Topic می‌تواند blocks استاندارد داشته باشد. در داده‌های قدیمی، concepts/formula/workedExample/commonError حفظ می‌شوند و موتور از `normalizeLearningTopicBlocks` برای نمایش canonical استفاده می‌کند.
10. پس از تغییر taxonomy یا mappingها، `npm run validate:learning` و `npm test` را اجرا کن.

### واژگان Tag پایه

Namespaceهای اولیه: discipline، competency-area، bloom-level، difficulty، question-format، assessment-purpose، exam-level، study-track، language و content-format.

وضعیت یادگیری داوطلب (weak/mastered/due/overdue) را در taxonomy محتوایی ثبت نکن؛ این وضعیت به پروفایل یادگیرنده تعلق دارد.
