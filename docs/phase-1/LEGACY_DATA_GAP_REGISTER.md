# ثبت شکاف‌های دادهٔ legacy در پایان مرحلهٔ اول

این سند مشخص می‌کند کدام بخش‌های فعلی مخزن هنوز با مدل مرجع مرحلهٔ اول هم‌خوان نیستند. در این مرحله، تغییر runtime انجام نشده تا مهاجرت ناسازگار با رابط‌های فعلی ایجاد نشود؛ اصلاح کد در مرحلهٔ سوم و با تست مهاجرت انجام خواهد شد.

## شکاف‌های تأییدشده

| محل | وضعیت موجود | مسئله | اقدام لازم |
|---|---|---|---|
| `src/data/examStructure.ts` | `MANAGEMENT_SUB_GROUPS` هفت گروه ثابت می‌سازد | مدل ۲۱۶۳/۲۱۶۴/۲۱۶۵ را به‌عنوان زیرگروه‌های ۲۱۶۲ نمایش می‌دهد؛ دفترچهٔ ۱۴۰۵ برای ۲۱۶۲ از کدهای ترکیب ۱ تا ۷ استفاده می‌کند | مهاجرت به `ExamSet → ExamCombination → Field → SubjectBundle` |
| `src/data/examStructure.ts` | `SUB_GROUP_SUBJECTS` دو درس تخصصی ثابت برای هر گروه می‌سازد | جدول ۱۴۰۵ بسته‌های ۳ تا ۹ دارد و بسته‌های یکسان در همهٔ ردیف‌ها اعمال نمی‌شوند | نگاشت ردیف‌به‌ردیف و سال‌دار |
| `src/data/examStructure.ts` | دروس با ضریب مستقل ۱ تعریف شده‌اند | منبع ۱۴۰۶ ضریب ۵ را برای مجموعهٔ دروس تخصصی اعلام می‌کند؛ ضریب مستقل تک‌درس‌ها از این اطلاعیه استنباط نمی‌شود | مدل‌سازی `coefficientScope` در سطح مجموعهٔ دروس |
| `src/data/examStructure.ts` | برای ۱۴۰۶ تعداد سؤال، مدت و نمره منفی از ۱۴۰۵ تکرار شده | این داده‌ها در اطلاعیهٔ عمومی ۱۴۰۶ که بررسی شد، احراز نشدند | خالی/نامعلوم تا استخراج دفترچهٔ ۱۴۰۶ |
| `content/research/official-exam-structure.md` | ادعا می‌کند ۲۱۶۳ تا ۲۱۶۵ کد زیرمجموعه‌اند و فقط ۷ گروه دارد | با جدول ۲۱۶۲ در دفترچهٔ ۱۴۰۵ همخوان نیست | این سند با مرجع و status جدید جایگزین شده |
| `src/data/examCoverage.ts` | پوشش دکتری فقط بر مبنای سؤالات دارای سطح دکتری محاسبه می‌شود | قبل از محاسبه باید دفترچه/سؤال رسمی واقعی و دامنهٔ دقیق ۱۴۰۶ ثبت شود | حفظ جداسازی، افزودن پوشش به تفکیک سال/ترکیب/درس پس از مرحلهٔ دوم |

## کنترل‌های لازم در مرحلهٔ سوم

- هیچ UI نباید از کدهای `MANAGEMENT_SUB_GROUPS` برای انتخاب ترکیب ۱۴۰۶ استفاده کند تا مهاجرت کامل شود.
- تست تطبیق داده باید نشان دهد هر فیلد/ترکیب فقط به درس‌های مجاز در همان سال وصل است.
- برای backward compatibility، شناسه‌های قبلی کاربران باید نگاشت مهاجرتی داشته باشند؛ رکوردهای قبلی حذف نشوند.
- هر API response مربوط به exam specification باید `examYear`, `sourceId` و `verificationStatus` داشته باشد.
- `getExamStructure(year)` نباید در صورت نبود نسخهٔ دقیق، بی‌صدا نزدیک‌ترین سال را برگرداند؛ مصرف‌کننده باید از fallback آگاه شود.
