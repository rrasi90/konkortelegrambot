# مشخصات گراف دانش و مدل سرفصل ــ مرحلهٔ اول

## ۱. هدف

گراف دانش باید رابطهٔ «آزمون رسمی، ترکیب، درس، مبحث، مفهوم، مهارت، سؤال و منبع» را قابل ردیابی کند. این گراف فقط نمودار نمایشی نیست؛ منبع تصمیم برای تعیین سطح، پیش‌نیاز، انتخاب سؤال، مرور و گزارش پوشش خواهد بود.

## ۲. سلسله‌مراتب و روابط

```text
ExamYear
  └── ExamSpecification
       └── ExamSet (مثلاً 2162)
            └── ExamCombination (کد ترکیب در همان سال)
                 └── ExamField / Track
                      └── ExamFieldSubjectAssignment (field-row-level mapping)
                           └── ExamSubjectBundle
                           └── Course
                                └── Chapter
                                     └── Topic
                                          └── Concept
                                               └── Skill
                                                    └── LearningOutcome

Question ──measures──> Skill (many-to-many)
Question ──appears_in──> OfficialExam / PracticePack
Question ──supported_by──> Source
Lesson ──teaches──> Topic / Concept / Skill
Resource ──covers──> Chapter / Topic / Concept
Skill ──prerequisite_of──> Skill
Concept ──related_to──> Concept
```

## ۳. موجودیت‌های اصلی

| موجودیت | شناسهٔ نمونه | مسئولیت |
|---|---|---|
| ExamSpecification | `exam:phd:1406` | نسخهٔ سالانهٔ مشخصات آزمون |
| ExamSet | `examset:phd:2162` | مجموعهٔ امتحانی |
| ExamCombination | `combination:phd:1405:2162:1` | ترکیب امتحانی با دامنهٔ اعتبار سالانه |
| ExamField | `field:business-marketing` | رشته یا گرایش مندرج در دفترچه |
| ExamSubjectBundle | `bundle:phd:1405:2162:3` | شمارهٔ بستهٔ درسی در جدول رسمی |
| ExamFieldSubjectAssignment | `assignment:phd:1405:2162:field-x` | نگاشت علامت‌های بستهٔ درسی به یک ردیف رشته/گرایش مشخص؛ مستقل از کد ترکیب |
| Course | `course:marketing-advanced` | درس علمی |
| Chapter | `chapter:marketing:consumer-behavior` | فصل آموزشی/مرجع |
| Topic | `topic:marketing:perception` | مبحث قابل آموزش |
| Concept | `concept:marketing:perceptual-map` | مفهوم مشخص |
| Skill | `skill:marketing:interpret-perceptual-map` | توانایی قابل سنجش |
| LearningOutcome | `outcome:marketing:interpret-map` | نتیجهٔ یادگیری قابل مشاهده |
| Question | `question:phd:1405:2162:...` | سؤال نسخه‌بندی‌شده |
| LearningResource | `resource:book:...` | کتاب، فصل، مقاله یا منبع |
| Evidence | `evidence:user:...` | شاهد عملکردی یادگیرنده |

## ۴. قوانین رابطه‌ها

1. رابطهٔ پیش‌نیاز `prerequisite_of` باید جهت‌دار و بدون چرخه باشد. چرخهٔ پیش‌نیاز باید در CI رد شود.
2. رابطهٔ «مرتبط با» می‌تواند چرخه داشته باشد؛ نباید با پیش‌نیاز یکی گرفته شود.
3. هر سؤال می‌تواند چند مهارت را بسنجد؛ هر مهارت باید بتواند با چند سؤال مستقل سنجیده شود.
4. هر مهارت می‌تواند به چند مبحث یا منبع متصل شود؛ اتصال صرفاً با عنوان متنی انجام نشود.
5. هر سؤال رسمی باید به سال، مجموعه، ردیف رشته/گرایش و بستهٔ درسی مربوط در همان سال، شماره سؤال و سند منبع متصل باشد. کد ترکیب به‌تنهایی جای نگاشت ردیف را نمی‌گیرد.
6. هر ردیف رشته/گرایش باید یک `ExamFieldSubjectAssignment` مستقل داشته باشد؛ کد ترکیب و بسته‌های علامت‌خورده جداگانه ذخیره و با تعریف رسمی کد ترکیب کنترل شوند. تعارض احتمالی باید به وضعیت review برود، نه اینکه با حدس رفع شود.
6. هیچ سؤالی صرفاً با داشتن `examYear` رسمی تلقی نمی‌شود؛ `provenanceType` و `verificationStatus` لازم‌اند.
8. رابطهٔ یک درس با یک ترکیب باید سال‌دار باشد؛ تغییر مواد در سال‌های بعد، دادهٔ گذشته را بازنویسی نمی‌کند.
8. اصطلاحات فارسی و انگلیسی در یک concept نگهداری می‌شوند، اما ID ثابت و مستقل از زبان است.

## ۵. طبقه‌بندی مهارت‌ها

مهارت‌ها باید قابل مشاهده و قابل سنجش باشند. برچسب‌های شناختی پیشنهادی برای سؤال و هدف یادگیری:

- `remember`: یادآوری تعریف، مؤلفه یا رابطه؛
- `understand`: توضیح و بازنمایی مفهوم؛
- `apply`: کاربرد قاعده یا مدل در موقعیت؛
- `analyze`: تفکیک اجزا، تشخیص رابطه و مقایسه؛
- `evaluate`: داوری مستدل دربارهٔ گزینه، مدل یا راه‌حل؛
- `create`: طراحی راه‌حل، مدل یا طرح پژوهش.

این برچسب‌ها توصیف سطح شناختی‌اند؛ نباید با دشواری آماری سؤال یکی شوند.

## ۶. رده‌های دشواری و اعتبار

`difficulty` دو نوع مقدار دارد:

- `expert_estimate`: تخمین اولیهٔ متخصص، پیش از پاسخ‌دهی واقعی؛
- `empirical_estimate`: تخمین مبتنی بر دادهٔ پاسخ داوطلبان.

مقادیر تجربی تا زمان جمع‌آوری نمونهٔ کافی `null` می‌مانند. مقدار تخمینی نباید در رابط به‌عنوان دشواری قطعی نمایش داده شود.

## ۷. مدل پوشش

برای هر سال و ترکیب، چهار پوشش جداگانه محاسبه شود:

1. **Exam-structure coverage:** آیا هر ماده/بستهٔ رسمی به درس‌های داخلی نگاشت شده؟
2. **Curriculum coverage:** چه نسبتی از مباحث مصوب در محتوای آموزشی وجود دارد؟
3. **Question coverage:** چه تعداد سؤال رسمی/تألیفی معتبر برای آن مهارت وجود دارد؟
4. **Evidence coverage:** چه مهارت‌هایی برای داوطلب با شواهد مستقل ارزیابی شده‌اند؟

این چهار درصد نباید با هم جمع یا جایگزین شوند. تعداد کتاب‌ها، فصل‌ها یا واژه‌های درسنامه نیز شاخص پوشش آزمون نیست.

## ۸. وضعیت‌های پیشنهادی

### اعتبار منبع
`official_primary`, `official_mirror`, `secondary_reliable`, `academic_primary`, `publisher_reference`, `internal_draft`.

### وضعیت تأیید
`draft`, `pending_source_check`, `pending_sme_review`, `verified`, `published`, `deprecated`.

### منشأ سؤال
`official_phd`, `official_msc`, `human_authored`, `ai_generated`, `diagnostic`, `transfer`.

### وضعیت انتشار محتوا
`draft`, `review`, `approved`, `published`, `retired`.

## ۹. قواعد صحت داده و کنترل خودکار

- ID یکتا و immutable؛
- تمام FKها باید resolve شوند؛
- سال منبع باید با سال رکورد سؤال سازگار باشد؛
- کد ترکیب فقط در دامنهٔ مجموعه و سال مربوط معتبر است؛
- سؤال رسمی بدون مرجع، شماره و وضعیت کلید تأییدشده منتشر نمی‌شود؛
- سؤالات AI و تألیفی هرگز در شمارش سؤال رسمی وارد نمی‌شوند؛
- مبحث بدون درس یا outcome در نقشهٔ یادگیری منتشر نمی‌شود؛
- مهارتِ دارای وضعیت mastered باید حداقل تعداد شواهد و تنوع سؤال تعیین‌شده در سیاست موتور را داشته باشد؛
- یال‌های پیش‌نیاز باید DAG باشند؛
- محتوای قدیمی با تغییر سند رسمی حذف نمی‌شود؛ نسخهٔ جدید با `effectiveFrom` ساخته می‌شود.

## ۱۰. تصمیم معماری

در مرحلهٔ اول فقط قرارداد مفهومی و دادهٔ مرجع تعریف می‌شود. ساخت Package مشترک، مهاجرت جداول و جایگزینی موتور legacy متعلق به مرحلهٔ سوم است. تا آن زمان، اپ نباید داده‌های این سند را به‌صورت دستی و جداگانه بازتولید کند؛ تغییر runtime باید در PR مرحلهٔ سوم انجام شود.
