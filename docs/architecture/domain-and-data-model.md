# مدل دامنه و داده

## سلسله‌مراتب محتوای آزمون

بستهٔ آزمون نسخه‌دار ← مقطع/آزمون ← گرایش و قواعد نمره‌دهی ← درس و ضریب ← سرفصل رسمی ← مهارت خرد ← منابع آموزشی و اقلام سنجش.

این‌ها یک درخت واحد نیستند. هر سؤال یا کارت می‌تواند چند مهارت را بسنجد و هر مهارت با چند سؤال، توضیح، مثال حل‌شده یا کارت مقایسه‌ای پوشش داده شود. رابطهٔ many-to-many صریح لازم است.

## موجودیت‌های اصلی

| موجودیت | مسئولیت |
|---|---|
| exam_packs | نسخه، وضعیت انتشار، منشأ و تنظیمات یک آزمون |
| exam_tracks | گرایش/مسیر و قواعد نمره‌دهی همان نسخه |
| track_courses | درس‌های هر مسیر، ترتیب و ضریب تأییدشده |
| syllabus_topics | ساختار سرفصل برای گزارش پوشش؛ منبع رسمی و وضعیت تأیید |
| atomic_skills | توانایی خرد و قابل سنجش با معیار عملکرد |
| skill_edges | رابطهٔ معنایی، منبع شواهد و وضعیت تأیید |
| learning_items | توضیح، مثال حل‌شده، سؤال تشخیصی، تست یا میکروکارت؛ همراه نسخه و وضعیت محتوا |
| item_skill_mappings | نگاشت چندبه‌چند قلم محتوا به مهارت |
| learner_events | رویداد تغییرناپذیر و idempotent کاربر |
| user_skill_states | projection قابل‌بازسازی از شواهد یادگیری |
| review_states | وضعیت حافظه و FSRS برای محتوای قابل مرور |
| planner_decision_logs | فعالیت انتخاب‌شده، دلایل، محدودیت و نسخهٔ موتور |
| study_profiles | آزمون هدف، تاریخ آزمون، بودجه و حالت مطالعه |

## گراف مهارت

- **prerequisite_of:** مهارت مبدأ پیش‌نیاز مهارت مقصد است؛ شکست در مهارت مقصد می‌تواند یک probe در پیش‌نیاز بسازد.
- **confusable_with:** دو مهارت مستعد اشتباه گرفتن با هم هستند؛ probe مقایسه‌ای ایجاد می‌کند.
- **applied_in:** انتقال کاربرد به درس دیگر را بررسی می‌کند؛ به‌تنهایی وضعیت تسلط را کاهش نمی‌دهد.
- **part_of:** برای تجمیع و گزارش سرفصل است؛ سبب انتشار تشخیصی نمی‌شود.
- **related_to:** پیشنهاد اختیاری برای مطالعه است.

هر یال باید وضعیت verification و منبع شواهد داشته باشد. یال ai_suggested صرفاً پیشنهاد است و حق تغییر اجباری صف را ندارد. نسخهٔ اول تنها روابط تأییدشدهٔ یک گام را بررسی می‌کند، نه پیمایش بازگشتی گراف.

## ثبت رویداد و وضعیت یادگیرنده

رویداد پاسخ حداقل زمان، کاربر، نسخهٔ آیتم و بسته، پاسخ خام، ترتیب گزینه‌ها، میزان اطمینان قبل از پاسخ، مدت پاسخ، حالت مطالعه، تکراری/دیده‌شده‌بودن و نسخهٔ الگوریتم را ثبت می‌کند. کلید idempotency باید برای هر درخواست منطقی یکتا باشد.

رویداد خام به‌روزرسانی یا حذف نمی‌شود. وضعیت فعلی بازسازی‌پذیر است و شامل برآورد عملکرد، اطمینان به شواهد، زمان پاسخ، الگوی غالب خطا و وضعیت پوشش می‌شود. عدد تسلط قطعی بدون عدم‌قطعیت نمایش داده نمی‌شود.

## Training و holdout

هر قلم محتوا برچسب training یا holdout_eval دارد. اقلام holdout در مسیر تمرین عادی و API کاربر قابل مشاهده نیستند و برای آزمون مستقل عملکرد روی سؤال دیده‌نشده رزرو می‌شوند. دسترسی به آن‌ها فقط از مسیر ارزیابی کنترل‌شده انجام می‌گیرد.

## حریم خصوصی و مجوز

شناسهٔ کاربر از Telegram به هویت سمت سرور نگاشت می‌شود؛ دادهٔ شخصی غیرضروری ذخیره نمی‌شود. سیاست RLS فقط بخشی از امنیت است و به‌تنهایی جایگزین اعتبارسنجی API نیست. منبع، نسخه، مجوز و وضعیت بازبینی هر بانک سؤال باید ثبت شود؛ مجوز انتشار عمومی تا پیش از بررسی مستقل قطعی فرض نمی‌شود.
