# مدل دامنه و داده

## مفاهیم اصلی

| مفهوم | معنی |
|---|---|
| **گرهٔ دانش (KnowledgeNode)** | یک مبحث مشخص در یک فصل از یک درس؛ کوچک‌ترین واحدی که تسلط روی آن سنجیده می‌شود. مثال: «دیدگاه مبتنی بر منابع» در فصل «دیدگاه‌های استراتژی» از درس «مدیریت استراتژیک پیشرفته». |
| **یال وابستگی (NodeDependency)** | رابطهٔ معنادار دو گره. جهت یال: `source` = مبحثی که خطا در آن رخ داده؛ `target` = مبحثی که اثر می‌پذیرد. |
| **سؤال (Question)** | ابزار سنجش؛ چندبه‌چند به گره وصل می‌شود (در نسخهٔ فعلی ۱ به ۱). |
| **کارت مرور (ReviewCard)** | وضعیت زمان‌بندی یک سؤال یا کارت دام برای یک کاربر مشخص. |
| **کارت دام (TrapCard)** | فلش‌کارت نکتهٔ دام تستی؛ از `trap_note` سؤال ساخته می‌شود و فقط یک‌بار (بدون تکرار). |
| **رویداد پاسخ (AnswerEvent)** | واقعیت خام و تغییرناپذیر: چه سؤالی، چه گزینه‌ای، کِی، با چه گزارشی. |

## انواع رابطهٔ یال

| نوع | معنی | اثر در موج خطا |
|---|---|---|
| `prerequisite` | target پیش‌نیازِ source است | لایهٔ ۳: کاهش تسلط + برنامهٔ ترمیم فردا |
| `cross_course` | target مفهوم هم‌ارز در درس/گرایش دیگر است | لایهٔ ۴: فقط اگر گرایش target برای کاربر فعال باشد |

وزن یال (`impact_weight`) بین ۰٫۲ و ۰٫۶ است و شدت سرایت را تعیین می‌کند.

## اسکیمای دیتابیس

مرجع کامل: [`supabase/migrations/0001_init.sql`](../../supabase/migrations/0001_init.sql)

### جداول محتوایی (مشترک بین همهٔ کاربران)

- `knowledge_nodes` — گره‌ها با `track` (common/business/technology)
- `node_dependencies` — یال‌ها با نوع و وزن
- `questions` — سؤال، گزینه‌ها (jsonb)، کلید، توضیح، نکتهٔ دام، `verification_status`
- `trap_cards` — کارت‌های دام (منبع: سؤال)

### جداول وضعیت کاربر

- `app_users` — کاربر، شناسهٔ تلگرام، گرایش‌های فعال، ظرفیت روزانه
- `user_node_mastery` — تسلط ۰ تا ۱۰۰ + وضعیت + `last_error_at`
- `review_cards` — زمان‌بندی هر کارت: `due_at`، `interval_days`، `previous_interval_days` (برای ترمیم)، `ease`، `is_repair`
- `daily_plan` — برنامهٔ روزانه با دلیل افزودن (`scheduled`/`sibling_shock`/…) و سقف بار
- `answer_events` — رویداد خام با قید یکتایی `(user_id, attempt_id)`

### وضعیت از عدد تسلط

| بازهٔ تسلط | وضعیت | رنگ در UI |
|---|---|---|
| کمتر از ۴۰ | `weak` (ضعیف) | قرمز |
| ۴۰ تا ۶۰ | `unstable` (متزلزل) | کهربایی |
| ۶۰ تا ۸۵ | `learning` (در حال یادگیری) | آبی |
| ۸۵ و بیشتر | `mastered` (تثبیت‌شده) | سبز |

## قواعد یکپارچگی

- کلید خارجی روی همهٔ ارجاع‌ها + `on delete cascade`
- `check` برای بازهٔ وزن یال (۰٫۲–۰٫۶)، تسلط (۰–۱۰۰)، سهولت (۱٫۳–۲٫۸)، `interval_days ≥ 1`
- یکتایی `(user_id, attempt_id)` برای idempotency
- یکتایی `(user_id, question_id)` برای کارت سؤال (کارت دام از طریق جدول جدا)
- RLS: خواندن عمومی محتوا؛ دادهٔ کاربر فقط با `auth.uid()` خودش

## نگاشت کاربر تلگرام به کاربر سامانه

`app_users.telegram_user_id` یکتاست و در اولین ورود معتبر initData ساخته می‌شود. نشست مینی‌اپ با توکن امضاشدهٔ HMAC (بدون افشای کلید سرویس) صادر می‌شود؛ کلاینت هرگز user_id را خودش تعیین نمی‌کند.
