# معماری سامانه

## نمای منطقی

1. **Telegram Mini App:** رابط React راست‌به‌چپ برای تمرین، بازخورد، برنامهٔ روز و نقشهٔ مهارت‌ها.
2. **Telegram Bot / Cloudflare Worker:** ورودی webhook و API؛ اعتبارسنجی درخواست، احراز هویت Telegram Mini App، کنترل مجوز و ثبت رویداد.
3. **هستهٔ دامنه و موتور تصمیم:** بستهٔ TypeScript مستقل از Telegram، HTTP و Supabase؛ منطق برنامه‌ریزی و تشخیص قابل‌آزمایش با ورودی قطعی.
4. **Supabase PostgreSQL:** بسته‌ها، سرفصل و مهارت، گراف روابط، بانک محتوا، رویداد تغییرناپذیر و projectionهای قابل‌بازسازی.
5. **موتور حافظه:** رابط مستقل برای FSRS؛ موعد مرور و وضعیت حافظه را مدیریت می‌کند، نه تشخیص علمی مهارت.
6. **مسیر محتوا:** ورود فایل منبع، استخراج اولیه، نگاشت پیشنهادی، بازبینی انسانی، انتشار بستهٔ نسخه‌دار.

## مرزهای مسئولیت

- هستهٔ دامنه از نام یک رشته، درس، تعداد گزینه یا ضریب آگاهی ندارد.
- Worker یک لایهٔ transport است؛ تصمیم یادگیری را با منطق موازی یا پرامپت مدل زبانی جایگزین نمی‌کند.
- رابط فقط تصمیم موتور را نمایش می‌دهد؛ خودش تسلط یا موعد مرور را محاسبه نمی‌کند.
- PostgreSQL منبع ثبت رویداد است؛ وضعیت مهارت و برنامهٔ مرور، نمای محاسبه‌شده و قابل بازسازی‌اند.
- موتور حافظهٔ FSRS فقط وقتی دربارهٔ مرور تصمیم می‌گیرد که محتوای مناسب برای مرور آماده باشد. ارزیابی اولیه و بازسنجی تشخیصی با آن یکی نیست.

## زیرساخت پیشنهادی

- **Cloudflare Workers:** webhook تلگرام و API سبک.
- **React + Vite:** مینی‌اپ و رابط موبایل.
- **Supabase PostgreSQL:** دادهٔ رابطه‌ای و دسترسی محدودشده به ردیف‌ها.
- **GitHub Actions:** typecheck، آزمون موتور و build؛ CI نباید به اسرار محیط production نیاز داشته باشد.

این‌ها انتخاب‌های اولیه‌اند، نه ادعای رایگان یا بی‌محدودیت‌بودن دائمی سرویس‌ها. پیش از deployment باید قیمت، سهمیه، region، محدودیت cron/background، نسخه‌های runtime و حفاظت از داده دوباره تأیید شوند. کار سنگین گراف در مسیر یک درخواست کوتاه اجرا نمی‌شود؛ در صورت نیاز به پردازش پس‌زمینه، باید صف یا job قابل retry با idempotency طراحی شود.

## امنیت حداقلی

- رازها فقط به‌صورت secrets سمت سرور؛ هیچ کلید service-role یا توکن بات با پیشوند VITE در مرورگر نیست.
- دادهٔ هر کاربر با RLS و شناسهٔ کاربر محدود می‌شود؛ نوشتن رویداد و projection فقط از مسیر قابل‌اعتماد سمت سرور انجام می‌شود.
- اعتبارسنجی HMAC دادهٔ Telegram WebApp، timestamp و سیاست replay قبل از اتصال واقعی Mini App اجباری است.
- rate limit، سقف حجم درخواست، ثبت خطای بدون اطلاعات حساس و بررسی شناسهٔ webhook پیش از عمومی‌سازی لازم‌اند.
- مایگریشن‌ها نسخه‌دارند؛ تغییر ساختار پایگاه داده روی محیط مشترک بدون backup و بررسی rollback اجرا نمی‌شود.

## وضعیت اجرا

Worker و Mini App فعلی اسکلت اولیه‌اند. endpointهای محصول، اتصال تلگرام، اعتبارسنجی initData، persistence واقعی، FSRS و استقرار production هنوز تکمیل نشده‌اند.
