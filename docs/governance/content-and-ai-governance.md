# حاکمیت محتوای آزمون و هوش مصنوعی

## وضعیت‌های محتوا (`verification_status`)

| وضعیت | معنی | رفتار سیستم |
|---|---|---|
| `unverified` | واردشده اما کلید/توضیح بازبینی نشده | به صف نمی‌رود |
| `verified` | بازبینی انسانی‌شده | به صف می‌رود |
| `quarantined` | مشکوک به کلید اشتباه یا اختلافی | از صف حذف؛ فقط برای تحلیل |
| `demo` | ساختگی، فقط برای توسعه و نمایش | به صف می‌رود (برچسب‌دار) |

## قواعد غیرقابل‌مذاکره

1. **کلید رسمی فقط با بازبینی انسانی تغییر می‌کند.** هوش مصنوعی حق تغییر مستقیم کلید، وضعیت مهارت یا موعد مرور را ندارد.
2. **هوش مصنوعی فقط پیش‌نویس می‌سازد:** نگاشت سؤال به گره، پیشنهاد یال، پیشنهاد توضیح و پیشنهاد نکتهٔ دام — همه به‌صورت پیشنهاد که انسان تأیید کند.
3. **یال‌های تأییدنشده اجازهٔ تغییر اجباری برنامه ندارند.** سرکوب خطا فقط روی یال‌های تاییدشده.
4. **سنجش نهایی با بانک قرنطینه:** سؤال‌هایی که داوطلب هرگز ندیده (سهم جداگانه از بانک)؛ نتیجهٔ این سنجش ملاک «تسلط واقعی» است نه تکرار سؤال‌های دیده‌شده.
5. **حقوق محتوا:** پیش از انتشار عمومی، مجوز استفاده از سؤالات رسمی آزمون بررسی می‌شود.

## فرایند درون‌ریزی محتوای واقعی

1. سؤالات خام → `content/packs/<pack>.json` (قالب `demo-pack.json`)
2. `node scripts/validate-content.mjs <pack>` — اعتبارسنجی ساختاری (ارجاع گره‌ها، وزن یال‌ها، گزینه‌ها)
3. بازبینی انسانی نگاشت‌ها و کلیدها
4. `node scripts/import-content.mjs <pack>` (یا `--sql` برای خروجی SQL)
5. ارتقای وضعیت به `verified` بعد از تأیید
